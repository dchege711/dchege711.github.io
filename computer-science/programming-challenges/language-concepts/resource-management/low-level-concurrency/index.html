Low Level Concurrency

Dated Oct 21, 2026; last modified on Wed, 21 Oct 2026

When a program runs, the OS creates a process – an isolated container with its own address space and resources. Inside that process, the OS or language runtime can create threads. A thread is an independent execution path with its own program counter, registers, and stacks, but it shares the heap, globals, and open resources with other threads in the same process. Concurrency exists whenever multiple threads can make progress independently and their execution can overlap. Even in a single-core environment, the OS rapidly switches between threads and interleaves their instructions.

The Problem

Some work should not be ran in the mainline as it takes too long, and makes your mainline unresponsive, e.g., on user signup, sending a welcome email should be done out of line lest your application cannot process new requests. Conceptually, API handlers produce tasks, workers consume tasks, and something sits in between to coordinate the handoff.

Three things need solving in this scenario:

  • Efficient waiting: Consumers should sleep when there’s no work, and wake up immediately when new work arrives.
  • Backpressure: Producers should slow down when consumers can’t keep up, preventing memory exhaustion which would take down the whole application.
  • Thread safety: The coordination mechanism itself must handle concurrent access without corruption.
