Low Level Design: Amazon Locker

Dated Oct 28, 2026; last modified on Fri, 30 Oct 2026

Design a locker system like Amazon Locker where delivery drivers can deposit packages and customers can pick them up using a code.

Clarifying Questions

  • Establish scope: Are we modeling just the piece from when the driver arrives at the locker until the customer? How does the customer get the code?
  • Questions on core flows: Are there different sized compartments? Can a small package go into a large compartment if the small ones are full? Are access tokens unique per package?
  • Edge cases: What if someone enters the wrong code multiple times? What happens to a package if it’s never picked up? What if all compartments of a given size are full when a driver tries to deposit?

Final Requirements

Requirements:

  • Carrier deposits a package by specifying a size (small, medium, or large). System assigns an available compartment of matching size, opens compartment and returns access token. Error if no space.
  • On successful deposit, an access token is generated and returned.
  • User retrieves by entering access token. System validates code and opens compartment. Throw specific error if code is invalid or expired.
  • Access tokens expire after 7 days. Customers can’t use expired codes. Package remains in compartment until staff removes it.
  • Staff can open all compartments with expired packages, remove the packages and return them to sender.
  • Invalid access tokens are rejected with clear error messages, e.g., wrong code, already used, expired.

Out of scope: delivery logistics for how the package gets to the locker; how the access token reaches the customer; lockout after failed access token attempts; UI/rendering layer; multiple locker stations; ayment or pricing.

Really gotta think like a PM here. My initial impression was that delivering the access token to the consumer was fair game. Also assumed that we’d need an audit trail for liability reasons. Assumed that difference in locker sizes was not in scope, and neither was reclaiming space from expired pickups.

Class Design

amazon_locker.h
#ifndef AMAZON_LOCKER_H
#define AMAZON_LOCKER_H

#include <cstddef>
#include <expected>
#include <map>
#include <string>
#include <vector>

#include "access_token.h"
#include "compartment.h"

namespace amazon_locker {

class AmazonLocker {
 public:
  struct CompartmentCounts {
    std::size_t small = 0;
    std::size_t medium = 0;
    std::size_t large = 0;
  };

  explicit AmazonLocker(CompartmentCounts counts);

  enum class DepositError : std::uint8_t { kNoAvailableCompartments };
  std::expected<std::string, DepositError> deposit_package(
      Compartment::Size size);

  enum class RetrievalError : std::uint8_t { kInvalidCode, kExpiredCode };
  std::optional<RetrievalError> retrieve_package(
      const std::string& access_code);

  void open_all_expired_compartments();

 private:
  Compartment* find_available_compartment(Compartment::Size size);
  void mark_available(AccessToken& access_token);

  std::vector<Compartment> compartments_;

  std::map<std::string, AccessToken> access_tokens_by_access_code_;
};

}  // namespace amazon_locker

#endif  // AMAZON_LOCKER_H

TIL that #pragma once is not universally supported, e.g., hard links, networked file systems. Thus, the #include guard macro is still king. Modules, introduced in C++20, eliminate the problem altogether because they are not handled by the pre-processor, and they can only be import at most once into a translation unit.

compartment.h
#ifndef COMPARTMENT_H_
#define COMPARTMENT_H_

#include <cstdint>

namespace amazon_locker {

class Compartment {
 public:
  enum class State : std::uint8_t { kAvailable, kOccupied };

  enum class Size : std::uint8_t { kSmall, kMedium, kLarge };

  explicit Compartment(Size size);

  void mark_available() { state_ = State::kAvailable; }

  void mark_occupied() { state_ = State::kOccupied; }

  bool is_available() const { return state_ == State::kAvailable; }

  Size size() const { return size_; }

 private:
  State state_ = State::kAvailable;
  const Size size_;
};

}  // namespace amazon_locker

#endif  // COMPARTMENT_H_

Physical state (contains a package, is broken, etc.) lives on the entity because it describes the entity’s condition. Relational state (assigned to this token, reserved by this user) lives in the orchestrator.

access_token.h
#ifndef ACCESS_TOKEN_H
#define ACCESS_TOKEN_H

#include <chrono>
#include <string>

#include "compartment.h"

namespace amazon_locker {
class AccessToken {
 public:
  AccessToken(std::string access_code, Compartment& compartment);

  bool is_expired() const {
    return std::chrono::system_clock::now() > expiry_date_;
  }

  const std::string& access_code() const { return access_code_; }
  Compartment& compartment() { return compartment_; }

 private:
  Compartment& compartment_;
  std::string access_code_;
  const std::chrono::time_point<std::chrono::system_clock> expiry_date_;
};
}  // namespace amazon_locker

#endif  // ACCESS_TOKEN_H

Implementation

amazon_locker.cc
#include "amazon_locker.h"

#include <algorithm>
#include <expected>
#include <optional>
#include <random>
#include <ranges>
#include <string_view>

#include "access_token.h"
#include "compartment.h"

namespace amazon_locker {

namespace {

std::string generate_access_code() {
  constexpr std::string_view charset = "0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ";
  constexpr size_t code_length = 6;

  // Set up thread-safe, non-deterministic random engine and distribution.
  std::random_device rd;
  std::mt19937 gen(rd());
  std::uniform_int_distribution<std::size_t> dist(0, charset.size() - 1);

  // Transform a sequence of random numbers into a string
  return std::views::repeat(0) |
         std::views::transform([&](int) { return charset[dist(gen)]; }) |
         std::views::take(code_length) | std::ranges::to<std::string>();
}

}  // namespace

AmazonLocker::AmazonLocker(CompartmentCounts counts) {
  for (size_t i = 0; i < counts.small; i++) {
    compartments_.emplace_back(Compartment::Size::kSmall);
  }
  for (size_t i = 0; i < counts.medium; i++) {
    compartments_.emplace_back(Compartment::Size::kMedium);
  }
  for (size_t i = 0; i < counts.large; i++) {
    compartments_.emplace_back(Compartment::Size::kLarge);
  }
}

std::expected<std::string, AmazonLocker::DepositError>
AmazonLocker::deposit_package(Compartment::Size size) {
  auto* compartment = find_available_compartment(size);
  if (compartment == nullptr) {
    return std::unexpected<AmazonLocker::DepositError>(
        AmazonLocker::DepositError::kNoAvailableCompartments);
  }

  std::string access_code;
  do {
    access_code = generate_access_code();
  } while (access_tokens_by_access_code_.contains(access_code));

  AccessToken access_token(access_code, *compartment);
  access_tokens_by_access_code_.emplace(access_code, std::move(access_token));
  compartment->mark_occupied();

  return access_code;
}

std::optional<AmazonLocker::RetrievalError> AmazonLocker::retrieve_package(
    const std::string& access_code) {
  if (access_code.empty()) {
    return AmazonLocker::RetrievalError::kInvalidCode;
  }

  auto it = access_tokens_by_access_code_.find(access_code);
  if (it == access_tokens_by_access_code_.end()) {
    return AmazonLocker::RetrievalError::kInvalidCode;
  }

  auto& access_token = it->second;
  if (access_token.is_expired()) {
    return AmazonLocker::RetrievalError::kExpiredCode;
  }

  mark_available(access_token);
  return std::nullopt;
}

void AmazonLocker::open_all_expired_compartments() {
  std::vector<AccessToken*> expired_access_tokens;
  for (auto& access_token : std::views::values(access_tokens_by_access_code_)) {
    if (access_token.is_expired()) {
      expired_access_tokens.push_back(&access_token);
    }
  }

  for (auto* access_token : expired_access_tokens) {
    mark_available(*access_token);
  }
}

Compartment* AmazonLocker::find_available_compartment(Compartment::Size size) {
  auto is_available = [size](Compartment& compartment) {
    return compartment.size() == size && compartment.is_available();
  };
  auto match = std::ranges::find_if(compartments_, is_available);
  return match == compartments_.end() ? nullptr : &*match;
}

void AmazonLocker::mark_available(AccessToken& access_token) {
  access_token.compartment().mark_available();
  access_tokens_by_access_code_.erase(access_token.access_code());
}

}  // namespace amazon_locker

An LLM helped me generate generate_access_code, and there’s stuff to unpack w.r.t. to views and pipelines.

A view is a lazily evaluated range that wraps another range and applies a transformation or filtering on demand, element by element, only as you iterate – without copying the original data, and with \(\mathcal{O}(1)\) move construction and destruction regardless of the number of elements. . This contrasts with range algorithms, which are applied to ranges eagerly.

Range adaptors are mechanisms for creating views, e.g., std::views::filter, std::views::transform, std::views::reverse, std::views::drop, std::views::keys, std::views::enumerate, std::views::zip, std::views::cartesian_product, std::views::cache_latest, etc.

Range adaptors overload operator| so that baz(bar(foo(vec), 3), 7) becomes vec | foo | bar(3) | baz(7). The pipe form resembles unix pipelines, and reads more naturally.

Views eliminate intermediate allocations and copies as they operate in a pull model. Only when the consumer asks for the next element does the request travel backward through the pipeline.

}
