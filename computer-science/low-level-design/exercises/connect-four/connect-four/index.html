Problem Statement

Build the object-oriented design for a two-player Connect Four game. Players take turns dropping discs into a 7-column, 6-row board. The first to align 4 of their own discs vertically, horizontally, or diagonally wins.

Requirements

These are guided by clarifying questions that determine the core operations to support, system states and their transitions, handling errors, and establishing scope.

  • Two players take turns dropping discs into a 7-column, 6-row board.
  • A disc falls to the lowest available row in the chosen column.
  • The game ends when:
    • A player gets 4 discs in a row (vertical, horizontal, or diagonal). They win.
    • The board is full. It’s a draw.
  • Invalid moves should be rejected early: dropping in a full column, moving out of turn, moving after the game is over.
  • Out of scope: UI support, concurrent games, move history, undo, board size configuration.

For out of scope, I also had: designing an AI opponent; multiplayer over the network. Variations like “sometimes the game allows a player to make two consecutive moves” directly contradict the prompt, despite them adding a twist to the game.

Core Entities and Relationships

The Player is identified by either Red or Yellow. The Board holds the discs, owns disc placement, and can tell if 4 discs are connected. The Game keeps track of whose Player’s turn it is, allows a Player to place a disc, and keeps track of the Won, Drawn, InProgress states.

Implementation

Using boolean flags for game state, e.g., isOver, hasWinner, and isDraw, makes impossible states representable despite your domain not allowing it, e.g., isOver=false and hasWinner=true is not prevented by the type system, but there can’t be a winner without the game being over.

I’ve been told to look into domain driven design before. This is a simplified example on the usefulness of creating types that are domain-driven.

Defining enum Player { Red, Yellow } and storing Players in Board leads to downstream complications, e.g., what if Player gets more properties? An enum DiscColor { Red, Yellow} maps better to the requirements, e.g., two players take turns dropping their own discs. 

namespace ConnectFour;

public enum DiscColor { Red, Yellow }

public record struct Player(string Name, DiscColor DiscColor);

public record struct Delta(int dR, int dC)
{
    public static Delta operator *(Delta delta, int factor) =>
        new(delta.dR * factor, delta.dC * factor);
}

public record struct Coordinate(int R, int C)
{
    public static Coordinate operator +(Coordinate coord, Delta delta) =>
        new(coord.R + delta.dR, coord.C + delta.dC);
}

Board.CheckWin can trip us into over-engineering. A polymorphic WinChecker, e.g., HorizontalWinChecker, VerticalWinChecker, etc., is over-engineered because we’ll never need another type of WinChecker, and we don’t need to swap out win-checking logic at runtime. 

﻿namespace ConnectFour;

public partial class Board
{
    public bool CanPlaceDisc(int column) =>
        column >= 0 && column < ColCount && _grid[RowCount - 1, column] == null;

    public bool IsFull() => Enumerable.Range(0, ColCount).All(c => _grid[0, c] != null);

    public Coordinate PlaceDisc(DiscColor color, int column)
    {
        if (!CanPlaceDisc(column))
            throw new InvalidOperationException($"Cannot drop into {column}");

        int row = Enumerable.Range(0, RowCount).First(r => _grid[r, column] == null);
        _grid[row, column] = color;
        return new(row, column);
    }

    public bool CheckWin(Coordinate coord)
    {
        if (!InBounds(coord))
            throw new InvalidOperationException($"{coord} is not on the game board.");

        return WinningDeltas.Any(delta => StreakInEitherDirection(coord, delta) >= StreakLengthForWin);
    }

    private bool InBounds(Coordinate coord) =>
        coord.R >= 0 && coord.R < RowCount && coord.C >= 0 && coord.C < ColCount;

    private int StreakInEitherDirection(Coordinate origin, Delta delta) =>
        StreakInDirection(origin, delta) + StreakInDirection(origin, delta * -1) + 1;

    private int StreakInDirection(Coordinate origin, Delta delta)
    {
        if (!InBounds(origin))
            throw new InvalidOperationException($"{origin} is not a valid starting point.");

        var targetColor = _grid[origin.R, origin.C];
        var streakLength = 0;

        for (int i = 1; i < StreakLengthForWin; i++)
        {
            var coord = origin + (delta * i);
            if (!InBounds(coord) || _grid[coord.R, coord.C] != targetColor)
                break;

            streakLength += 1;
        }

        return streakLength;
    }

    private const int RowCount = 6;
    private const int ColCount = 7;
    private const int StreakLengthForWin = 4;
    private readonly IReadOnlyList<Delta> WinningDeltas =
        [new Delta(0, 1), new Delta(1, 0), new Delta(1, 1)];

    private readonly DiscColor?[,] _grid = new DiscColor?[RowCount, ColCount];
}

argues that Game shouldn’t call CanPlaceDisc first; for separation of concerns, Board.PlaceDisc should internalize the CanPlaceDisc check, returning a sentinel value when the placement fails. I disagree. Game still needs to know about the sentinel value and so there’s not really a separation of concerns; I prefer an explicit CanPlaceDisc call.

namespace ConnectFour;

public partial class Game(Player _player1, Player _player2)
{
    public enum State { InProgress, Won, Drawn }

    public Player CurrentPlayer() => _currentPlayer;

    // Made virtual for extensibility, see GameWithUndo.
    public virtual Coordinate PlaceDisc(Player player, int column)
    {
        if (GetState() != State.InProgress)
            throw new InvalidOperationException($"No moves allowed when Game is in the {GetState()} state.");

        if (CurrentPlayer() != player)
            throw new InvalidOperationException($"It's not {player.Name}'s turn");

        if (!_board.CanPlaceDisc(column))
            throw new InvalidOperationException($"No disc can be dropped into {column}");

        var restingSpot = _board.PlaceDisc(player.DiscColor, column);

        if (_board.CheckWin(restingSpot)) { _gameState = State.Won; }
        else if (_board.IsFull()) { _gameState = State.Drawn; }
        else { _currentPlayer = _currentPlayer == _player1 ? _player2 : _player1; }

        return restingSpot;
    }

    public State GetState() => _gameState;

    public Player? Winner() => _gameState == State.Won ? _currentPlayer : null;

    protected Player _currentPlayer = _player1;
    protected Board _board = new();

    protected State _gameState = State.InProgress;
}

Extensibility: Supporting Undo

Supporting Undo tests whether your design has a clean separation between orchestration (Game) and state (Board). 

namespace ConnectFour;

public class GameWithUndo(Player player1, Player player2) : Game(player1, player2)
{
    public override Coordinate PlaceDisc(Player player, int column)
    {
        var destination = base.PlaceDisc(player, column);
        movesHistory.Push(new(player, destination));
        return destination;
    }

    public bool Undo()
    {
        if (GetState() != State.InProgress)
            throw new InvalidOperationException("Undo is only supported for in-progress games.");

        if (!movesHistory.TryPop(out var lastMove))
            return false;

        _board.Clear(lastMove.Coordinate);
        _currentPlayer = lastMove.Player;
        return true;
    }

    record struct Move(Player Player, Coordinate Coordinate);

    private Stack<Move> movesHistory = [];
}

namespace ConnectFour;

public partial class Board
{
    public void Clear(Coordinate coord)
    {
        if (!InBounds(coord))
            throw new InvalidOperationException($"{coord} is not on the game board.");

        var isTopMost = coord.R == RowCount - 1 || _grid[coord.R + 1, coord.C] == null;
        if (!isTopMost)
            throw new InvalidOperationException($"A disc sits atop {coord}.");

        _grid[coord.R, coord.C] = null;
    }
}

Extensibility: Adding a Computer Opponent

An abstraction atop Player (e.g., HumanPlayer, BotPlayer) doesn’t add much value because HumanPlayer doesn’t “do” anything. Instead, change the game loop. 

namespace ConnectFour;

public partial class Board
{
    public Board()
    {}

    public Board(Board other)
    {
        for (int r = 0; r < RowCount; r++)
        {
            for (int c = 0; c < ColCount; c++)
            {
                _grid[r, c] = other._grid[r, c];
            }
        }
    }

    public int GetColCount() => ColCount;
}

namespace ConnectFour;

public partial class Game
{
    public Board GetBoard() => new(_board);
}

namespace ConnectFour;

public interface IBotEngine
{
    int ChooseColumn(Game game);
}

public class FirstAvailableSpotBotEngine : IBotEngine
{
    public int ChooseColumn(Game game)
    {
        var board = game.GetBoard();
        for (int c = 0; c < board.GetColCount(); c++)
        {
            if (board.CanPlaceDisc(c))
                return c;
        }

        throw new InvalidOperationException("No spots available on board.");
    }
}

public class LastAvailableSpotBotEngine : IBotEngine
{
    public int ChooseColumn(Game game)
    {
        var board = game.GetBoard();
        for (int c = board.GetColCount() - 1; c >= 0; c--)
        {
            if (board.CanPlaceDisc(c))
                return c;
        }

        throw new InvalidOperationException("No spots available on board.");
    }
}

namespace ConnectFour.Tests;

[TestClass]
public sealed class GameLoopTests
{
    [TestMethod]
    public void GameLoop_Completes()
    {
        // Arrange
        Player player1 = new("Vision", DiscColor.Red);
        Player player2 = new("Ultron", DiscColor.Yellow);
        Game game = new(player1, player2);

        IBotEngine engine1 = new FirstAvailableSpotBotEngine();
        IBotEngine engine2 = new LastAvailableSpotBotEngine();

        // Act: Have each bot take turns.
        while (game.GetState() == Game.State.InProgress)
        {
            var player = game.CurrentPlayer();
            var column = player == player1
                ? engine1.ChooseColumn(game)
                : engine2.ChooseColumn(game);
            game.PlaceDisc(player, column);
        }

        // Assert.
        Assert.AreEqual(player1, game.Winner());
    }
}
